# Reversing roadmap / session notes

Goal: fully understand `Shannara Demo.asm` (the DEMO.LE disassembly) well
enough to inform reimplementing the full Shannara game (Legend
Entertainment, ScummVM-style engine reimplementation). The demo is
non-interactive (confirmed — see `analysis/entry_and_init_flow.md`), so a
lot of real gameplay code (room logic, dialogue, inventory, etc.) is either
absent from this binary or present-but-unreachable from the demo's `main`.
Treat everything reachable as ground truth for the shared engine; treat
everything unreachable as "probably real, but unverified against actual
runtime behavior in this binary."

## Working constraints

- **Do not script against the live `.idb`/`.id0`/`.id1`/`.nam`/`.til` files
  while IDA Pro's GUI has the database open** (check with `tasklist | grep
  ida` before ever considering `idat64 -S...`). All analysis in this folder
  so far was done by reading the **exported** `Shannara Demo.asm` text only
  — safe, read-only, no risk to the live session. If you want findings
  applied back into the actual IDB (renames, struct edits, comments), either
  write an IDAPython script into `scripts/` for the user to run themselves
  inside their own IDA session, or wait until IDA is confirmed closed.
- The `.asm` export is regenerated periodically; line numbers cited in
  `analysis/*.md` will drift. Prefer citing function/symbol names (grep-able)
  over line numbers where possible; where line numbers are cited, treat them
  as "as of this pass."
- `analysis/engine_overview.md` is a **copy** of the top-level
  `Shannara Demo Analysis.md` from an earlier pass (kept as the master
  narrative doc going forward — edit the copy in this folder, not the
  original at the project root, so this becomes the single source of
  truth). It already has an addendum pointing at the newer docs.

## What's understood so far

1. `analysis/engine_overview.md` — third-party libraries (Miles/AIL, Watcom
   CRT, MS C graphics lib), 15 structures, and the picture/UI/memory/cutscene/
   palette subsystems. (Earlier pass.)
2. `analysis/entry_and_init_flow.md` — the complete `main()` control flow.
   The demo is a fixed non-interactive intro-reel player driven by
   `flix_play`; confirms room/UI/game-logic code is linked in but dead in
   this build.
3. `analysis/drawing_primitives.md` — resolves 7 of the 22 previously-unnamed
   `sub_XXXXXX` functions as a pixel/line "graphics pen" API (`get_pixel`,
   `put_pixel`, `draw_line`, `set_gr_op`/`get_gr_color`, `line_to`) sitting
   below the `gx*` blitter layer, and classifies the other 13 as third-party
   library internals (Miles/AIL, Watcom CRT DOS-extender plumbing) — not
   worth further attention. Only `sub_1652E0` (Q-codec, already known-deep)
   and `sub_17DC6C` remain genuinely uncharacterized.
4. `analysis/compression_lzhuf.md` — **important correction**: `Pic`
   decompression (`gxVirtualDecompress` -> `CXBUF2BUFEXPAND`) is LZHUF
   (LZSS + adaptive Huffman, the classic Yoshizaki `lzhuf.c`/LHA algorithm),
   not RLE. Public/well-documented algorithm — a real shortcut for
   reimplementation once the exact parameters are confirmed.
5. `analysis/function_inventory.json` — mechanical per-function inventory
   (name, line range, size, rough xref count, library/engine/unnamed
   bucket) generated by `scripts/parse_asm.py`. Re-run after any new `.asm`
   export.

## High-value resources discovered this pass (not previously in the notes)

- **`..\xanth\` folder**: an IDB (`Xanth.idb`) and a `.BinExport`/`.BinDiff`
  for another Legend Entertainment title ("Companions of Xanth", built on
  what's very likely the same in-house engine), plus a **pre-existing
  `xanth_vs_Shannara Demo.BinDiff`** comparing the two binaries. This wasn't
  referenced anywhere in the existing analysis. A BinDiff between two games
  on the same engine is an excellent way to (a) confirm which functions are
  truly shared-engine vs. Shannara-specific, and (b) potentially pull better
  names/signatures from whichever binary has more complete debug info.
  **Suggested next step:** open the BinDiff and cross-reference its matches
  against the "engine_named"/"unnamed" buckets in `function_inventory.json`.
- **`..\Shannara.idb`**: appears to be a separate (larger, 2.3MB vs. the
  demo's ~1MB) database — very likely the **full retail game**, not just the
  demo. If so, this is the actual end-goal target and probably contains all
  the room/gameplay logic this demo binary has linked-but-dead. Worth
  understanding its relationship to `Shannara Demo.idb` explicitly (same
  engine version? Same base addresses? Can structures/names be transplanted
  directly?) before investing further in the demo alone.
